5. Deployment Steps Still Pending

  1. Revert and rotate. Complete F1 and F2 before anything is deployed or committed.
  2. Commit. Clear the index (F6), then commit the frontend, the backend, and the lock files in logical groups.
  3. Decide the domain. The final domain, plus www if it is used. Set DNS and TLS for it.
  4. Supabase. Create the production project. Copy its CA certificate for DB_SSL_CA. Apply the schema with npm run db:update, enable backups, and test a restore. Never run db:reset against data.
  5. Render. Create the service from render.yaml. Enter the secrets it marks for dashboard entry, including FRONTEND_ORIGIN, CORS_ORIGINS and DB_SSL_CA. Deploy, then check /health and /health/ready. Start with one instance. Add instances only when load needs them, and only after REDIS_URL is set on the service.

  8. Verify. Run section 3 checks C1, C3, C4, C5, C6 and C8 against the live domain. Check the response headers with curl -I.
  9. Rollback. Keep the previous dist/ upload. In Render, roll back to the previous deploy. Take a database backup before any schema change.
